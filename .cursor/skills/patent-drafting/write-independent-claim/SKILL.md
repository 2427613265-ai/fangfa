# 独权撰写

权利要求书中最重要的一步。发明人交底只是优选方案；独权必须围绕与现有技术的**核心区别**重新概括，做到「顶天立地」：范围尽量大而合理，同时仍是可实现的完整技术方案，能在现有技术迷雾里站住。

不写从属权利要求、不写说明书。关键创新点只登记、留给 `write-dependent-claims`。

## 何时启用

- 理解稿 + 命名表已齐，进入独权
- 用户要求写 / 改独立权利要求
- 无理解稿：先 `understand-disclosure`。无命名表：先 `name-components`，本步不得宣称定稿
- 不要因自行评估创造性弱而启用 `reinforce-inventiveness`

## 工作方式：分步输出

默认**一轮只做下面一个步骤**，写入 `03-independent-claim.md` 对应节后停下，等用户继续或修改。用户说「一次写完」才可同轮做多步。

不要用理解稿里的「必要特征候选」直接当独权特征表。那些是理解阶段的分流，本 skill 必须按下列步骤**重新构造**。

---

## 步骤一：确定核心区别技术特征（和关键创新点）

先对齐理解稿中的现有做法 / 最接近手段（只据交底与理解稿，不编造对比文件），再做两件事。

### 1. 核心区别技术特征（独权的出发点）

找出：能使本方案与现有技术分开，又能使保护范围尽量大的那个区别。它应落在「待申请技术与现有技术的边界」上，并表明本申请站在边界这一侧。

用**一句话**概括（核心区别的「一句话描述」）。这句话是抽象技术方案的出发点，不是实施例标题，也不是交底里的发明名称。

要求：

- 从交底与现有技术的差异出发，不要把优选实施例（如某一种滑动轨迹）当成核心区别本身
- 概括后应能看见一簇实现，而不是只看见交底那一个点子
- 符合技术逻辑、有实现可能即可，不要求交底已经列举全部变体
- 方法：区别往往在步骤、条件、对象上的动作关系；结构：区别往往在构件、连接、位置或配合关系

**反例意识**：现有技术是按键解锁、本申请交底是滑块滑动解锁时，核心区别应提到「用触摸屏上的特定触摸动作解锁」，而不是写成「必须滑动一块解锁图像」。一句话对了，独权才可能顶天。

### 2. 关键创新点（给从权，不塞进独权）

在优选实施方式里，标出：解决了关键难点、构思最巧、最不易想到、或构成显著特点的点。可以有多个；改进较小的案子里，可能与核心区别高度重合。

关键创新点用来指示从权分层，**不要为了「写得更像交底」而写进独权**。本步只列表并说明为何留给从权。

本轮输出：一句话描述、为何是边界、关键创新点清单（及不进独权的理由）。然后停下。

---

## 步骤二：构造最小技术特征集

以步骤一的一句话为中心，展开成**完整技术方案**所必不可少的特征。这个集合叫最小技术特征集。

### 硬规则

最小技术特征集 = **构成完整方案**所不可缺少的特征。

它**不是**「为了解决交底书所写技术问题而堆起来的特征集合」。交底问题往往绑着优选实施例和全部技术效果；按问题清单凑独权，会把非必须特征写进去，范围立地有余、顶天不足。

因此：

- 只保留：没有它，围绕该核心区别的方案就连不成、做不成或说不清的特征
- 不引入：仅用于交底某一效果、某一工况、某一优选结构/参数、某一关键创新点的特征
- 一句话里含糊的词（如「特别的触摸动作」）要换成权项里能看懂的表述（如「预先设定的解锁触摸动作」），这是说清楚，不是加限定
- 为把特征连成方案，需要状态、对象、连接关系等骨架词时，可以进入本集合（如锁定状态 / 工作状态）；它们是完整性，不是优选细节
- 同一对象用命名表中的同一名称；本步仍可标「拟上位」的候选，留给步骤五

方法：列出能走完一遍的最少步骤及步骤间必要关系。  
结构：列出能构成该装置/系统的最少部件及必要连接、位置或配合。  
方法+结构：先判断核心区别落在方法、结构还是两者都要单独成项；不要用一项独权硬绑两套完整发明。

本轮输出：特征表（名称、为何必不可少、若不纳入方案何处断裂）。明确写出哪些理解稿「必要特征」被剔除及原因。然后停下。

---

## 步骤三：根据最小技术特征集写第一版独权

把最小技术特征集连缀成一项完整独立权利要求。特征之外允许有连接用语，但不得借连接语夹带新的实质性限定。

行文：

- 前序给出技术主题 + 已知部分（有则写）；特征部分写区别与必要配合
- 方法：`一种……的方法，其特征在于，包括：` 步骤清楚、顺序或条件关系明确
- 结构：`一种……，其特征在于，包括：` 部件及必要连接/位置写清
- 不用纯效果、纯原理、商业目的当特征
- 术语与命名表一致；一句话描述里的核心区别必须能在正文中找到对应，而不是写回实施例细节

第一版的技术主题可以暂用交底对象（如「触摸屏手机」），步骤四再审定。不要在本步提前把从权细节写进来。

本轮输出：第一版独权正文 + 与最小特征集的逐条对应。然后停下。

---

## 步骤四：根据第一版，重新核定技术问题（并审定技术主题）

第一版写出来之后，**不要继续沿用交底书原来的技术问题**当独权的问题。交底问题是发明人站在优选实施例上提的；独权是抽象方案，问题必须按第一版实际包含的特征重新核定。

做两件事：

1. **重核要解决的技术问题**  
   问：第一版这套特征真正解决的是什么问题？问题应与第一版方案匹配：不能宽到方案支撑不住，也不能窄到只剩交底实施例的口号。理解稿中的原问题可作对照，冲突时以第一版方案为准，并写明为何调整。

2. **审定技术主题**  
   原主题多半过窄（发明人领域习惯）。看第一版全部特征实际能覆盖的对象与领域，主题过窄则拓宽（手机→触摸屏设备；内燃机→往复-旋转转换机构这类），过宽则收窄。实用新型对主题宽窄更敏感；发明一般不必靠缩领域来「增加创造性」。主题过宽、过窄都要写理由。

本轮只核定问题和主题，不在本轮改写完整第二版正文（用词替换可先点出）。然后停下。

---

## 步骤五：在新问题下改写，输出第二版独权

在新的技术问题与技术主题下，回头看第一版是否还合适，并**进一步删减和上位**。

- **是否还合适**：每个特征是否仍为「新问题下完整方案」所必须；是否只是旧问题或优选实施例带来的多余限定
- **删减**：能去掉仍完整、仍能体现核心区别的，去掉
- **上位**：对象、步骤、结构关系能合理概括的，概括（具体手势→预定触摸动作；手机→设备）。上位须有技术逻辑和实现可能，不能空到与现有技术不再有边界
- **用语对齐**：正文中的主题词与前序技术主题一致
- **立地**：删减/上位后仍须是完整可实现方案；核心区别的边界还在。不要为了顶天写成口号

第二版是本 skill 交给下游的独权。第一版保留在同一文件中对照。上位若超出命名表，列出拟回写命名表的名称，不要假装命名表已改。

方法+结构若步骤一、二已决定两项独权：每项各自走完第一版→重核问题/主题→第二版，不要混成一项。

本轮输出：第二版正文、相对第一版的删减/上位对照、核定后的技术问题与技术主题、留给从权的关键创新点。第二版经用户认可前，不要宣称独权定稿。

---

## 顶天 / 立地（贯穿各步）

- **顶天**：独立权利要求尽量贴近「与现有技术边界上、范围最大」的那一句话，而不是交底实施例的说明书缩写
- **立地**：必须是完整技术方案，特征清楚、能实现；面对尚未检索到的现有技术，不靠堆优选细节来「保授权」，而靠最小完整方案仍然站在边界这一侧
- 第一次出价要高而合理（第一版围绕核心区别展开）；保底不是把交底步骤全写进独权，而是第二版仍完整、仍有区别

## 方法 / 结构

| | 方法 | 结构 |
| --- | --- | --- |
| 核心区别 | 步骤或条件上的边界 | 部件或连接/位置上的边界 |
| 最小集 | 最少步骤 + 必要关系 | 最少部件 + 必要配合 |
| 独权骨架 | 主题 + 步骤链 | 主题 + 部件及连接 |

## 输出文件

`cases/<案号>/03-independent-claim.md`（案号未知用 `draft`），随步骤追加：

1. 核心区别一句话 + 关键创新点
2. 最小技术特征集（含剔除说明）
3. 第一版独权
4. 重核后的技术问题 + 技术主题
5. 第二版独权 + 删减/上位对照
6. 下游指针：关键创新点、未进独权的优选特征（不写从权文句）

## 边界

- 上游：`01-understanding.md`、`02-naming.md`；有补强则加读 `01b-inventiveness-reinforcement.md`
- 下游：`write-dependent-claims` 读第二版独权与关键创新点；实施例与说明书发明内容与第二版对齐
- 不在本 skill 展开从权或实施例
