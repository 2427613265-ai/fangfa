# 交底书理解（架构）

**流水线第 1 步。** 写独权之前必须完成。本阶段只定职责与契约，撰写/提炼细则待补。

## 架构角色

把发明人口语或书面交底，变成下游 skills 可引用的「技术方案理解稿」。独权能否写对，取决于本步是否把必要特征、发明点和方案边界吃准。

## 何时启用

- 全流程 `/draft-patent` 的第一步
- 用户要求理解交底、梳理技术方案、提炼发明点
- 即将写权利要求，但上下文还没有理解稿

## 门禁

- 无交底材料（文本/图/问答）时：先要材料，不编造技术方案。
- 本 skill **不输出**权利要求书或说明书章节。

## 输入 / 输出契约

**输入**

- 交底书、附图说明、口头补充、现有技术对比（有则用）

**输出**（`01-understanding.md`，章节细目待补，至少要能支撑下游）

- 发明类型：`方法` / `结构` / `方法+结构`
- 要解决的问题与最接近现有技术（据交底）
- 技术方案主线（方法：步骤链；结构：部件及连接/位置关系）
- 必要特征候选 vs 优选/附加特征候选（供独权/从权分流）
- 效果与数据（仅交底已有）
- 缺口与待向发明人确认的问题

## 上下游

- 上游：用户交底
- 下游必读：`name-components`、`write-independent-claim`、`write-dependent-claims`、`write-embodiments`、`write-specification-other`
- 可选旁路：`reinforce-inventiveness`（不得由本 skill 建议或自动转入；仅用户事后明确启动）

## 与命名 skill 的边界

本步可以列出「对象清单」（出现过的部件、步骤、物料），但**不在此定稿名称**。正式命名交给 `name-components`。

- 发明点分层规则（何入独权、何入从权）
