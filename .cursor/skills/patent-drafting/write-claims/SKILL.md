# 权利要求书撰写（架构）

在 `conceive-independent-claim` 交出第二版独权并被本 skill **接受**之后，撰写完整权利要求书。从权细则待补。

**接受之后的第一件事：启用 `name-components`。** 对独权中的命名和交底书中的命名一并做符合专利要求的优化。没有命名表，不得写权利要求书正文（含不得用正式用名改写独权、不得写从权）。

本 skill 不改独权的技术特征集合（删减/上位属于独权构思）。命名只换标签，不换方案。若命名后发现特征集合有问题，停写并回到 `conceive-independent-claim`。

## 何时启用

- 独权构思第二版已完成，用户要写权利要求书或从权
- 用户要求权项布局、补从权、用正式名称落权项
- 无独权构思结果：先启用 `conceive-independent-claim`，不在本 skill 里临编独权

## 门禁与顺序

1. 必须已有 `02-independent-claim.md`（第二版独权）。接受该独权（用户确认或本轮明确接手）。
2. **立即**启用 `../name-components/`：输入为该独权用名 + 交底/理解稿用名。
3. 必须已有 `03-naming.md` 之后，才允许：
   - 把独权改写成命名表中的正式用名（特征集合不变）
   - 撰写从属权利要求
4. 不写说明书章节。

## 输入 / 输出契约

**输入**

- 独权构思第二版、最小特征集、关键创新点（`02-independent-claim.md`）
- 命名表（`03-naming.md`，本 skill 接受独权后先产出）
- 理解稿中的优选 / 附加特征

**输出**（`04-claims.md`，从权体例待补）

- 使用正式名称改写后的独立权利要求
- 从属权利要求列表（编号接续独权）
- 引用关系说明（待补）
- 未写入从权、仅拟放说明书的特征（如有）

## 上下游

- 上游：`conceive-independent-claim` →（本 skill 接受后）`name-components`
- 下游：`write-embodiments`、`write-specification-other`（须与正式用名独权及从权一致）

## 方法 / 结构

架构预留（从权规则待补）：方法从权（参数、附加步骤、工况等）与结构从权（材料、尺寸、连接变体、可选部件等）。

## 内容待补

- 用正式名称改写独权的对照检查
- 从权分层与引用规则（关键创新点优先布置）
- 单引 / 多引策略
