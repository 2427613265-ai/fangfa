# 部件命名（架构）

**横切 skill。** 位于理解之后、独权定稿之前；权项与说明书全文共用同一张命名表。本阶段只定职责与契约，命名细则待补。

## 架构角色

权利要求里的名称一旦写下，说明书必须跟着用。命名独立成 skill，避免独权、从权、实施例各自临时起名。

「部件」在此泛指需要稳定称谓的技术对象：

- 结构专利：零件、模块、连接关系、位置关系用语
- 方法专利：步骤名、操作对象、介质、工装、中间产物

## 何时启用

- 理解稿完成后、写独权前（全流程强制）
- 用户要求命名、术语表、统一叫法
- 后续撰写中出现新对象，需要增补命名表时再入一次

## 门禁

- 前置：已有 `understand-disclosure` 的理解稿（至少有对象清单）。
- 无命名表，`write-independent-claim` 不得宣称定稿。
- 本 skill **不撰写**权利要求或实施例正文。

## 输入 / 输出契约

**输入**

- 理解稿中的对象 / 步骤 / 部件清单
- 交底原文用词（作对照，不一定采用）

**输出**（`02-naming.md`，表结构待补）

- 正式名称（权项与说明书唯一用语）
- 交底别称 / 禁止再用的同义词
- 发明类型相关字段（结构：隶属关系；方法：步骤顺序中的对象）
- 未命名或有争议项（标待确认，不擅自定稿关键名）

## 上下游

- 上游：`understand-disclosure`
- 下游必读：`write-independent-claim`、`write-dependent-claims`、`write-embodiments`、`write-specification-other`

## 内容待补

- 命名原则（上位/下位、避免功能纯描述、避免商标等）
- 方法 vs 结构的命名表字段
- 增补与改名时如何回写已有权项
