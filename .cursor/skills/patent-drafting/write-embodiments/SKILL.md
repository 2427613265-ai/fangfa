# 具体实施例（架构）

**说明书的一半：具体实施方式。** 本阶段只定职责与契约，实施例写法待补。

## 架构角色

把权项中的技术方案写成可实施的具体例子。必须支撑独权全部必要特征；命名与权项一致。与 `write-specification-other` 拆开，避免实施例细节与背景/发明内容混写。

## 何时启用

- 权项已相对稳定（至少独权已有）
- 用户只要实施例 / 具体实施方式
- 全流程中与「说明书其他部分」可并行，但都应读取同一套权项与命名表

## 门禁

- 必须已有理解稿、命名表、独权。
- 从权已有则一并支撑；无从权可先写覆盖独权的实施例。
- **不写**技术领域、背景技术、发明内容、附图说明等（那些属于 `write-specification-other`）。

## 输入 / 输出契约

**输入**

- 理解稿中的可实施细节、参数、变例素材
- 命名表
- 独权（及从权，若有）

**输出**（`05-embodiments.md`）

- 具体实施方式正文（结构待补：主实施例、替代例、对应附图标记等）
- 与独权必要特征的覆盖对照（格式待补）

## 上下游

- 上游：理解稿、命名表、独权、从权
- 并列：`write-specification-other`
- 总控可将本输出编入 `specification.md`

## 方法 / 结构

架构预留分支（规则待补）：方法实施例（步骤、条件、参数）与结构实施例（部件装配、位置、工作过程）。

## 内容待补

- 实施例展开规则、与权项一致性
- 多实施例 / 变例组织
- 附图标记与命名表的对应
