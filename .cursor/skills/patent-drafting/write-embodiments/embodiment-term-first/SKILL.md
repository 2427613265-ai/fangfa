# 具体实施方式：先释义新名词，再展开实施例

## 核心规则

在"具体实施方式"部分为**某一条权利要求**撰写实施例时，如果这条权利要求里含有**不清楚的、新定义的名词**（撰写者自造的术语、被赋予特殊含义的普通词、本发明特有的参数或量），必须按以下顺序动笔：

```
第一步：按 `embodiment-drafting` 写该条的复述段
第二步：另起一段，逐个解释本条里的新定义名词——是什么、怎么算、由哪些已知量构成
第三步：名词清楚后，再按 `embodiment-drafting` 写展开段（从名称+标号或工序写起，不要用「具体而言，」起句）
```

释义段紧挨在复述之后、展开之前。不要混进复述，也不要拖到展开里边讲边猜。

释义起句用「某某是指……」或「本实施例中，某某为……」。不要用「具体而言，」「进一步地，所述某某……」。第一次解释该名词时不要加「所述」。

## 为什么要先释义

- 实施例是用来把权利要求讲透的，如果实施例里用到的核心名词读者还不理解，整段实施例就读不通，起不到"讲透"的作用。
- 先把名词钉死，后面展开原理和操作流程时可以直接引用这些名词，行文连贯、不必反复打断去解释。
- 说明书里对新名词的这段解释，也正是权利要求中该名词"得到说明书支持"的落脚点。

## 与权利要求侧就地说清的分工

- 权利要求内部：非公知概念须**自足说清**（见 权利要求书撰写中的就地定义要求）——优先改自明名或在名称出现前白话描述；「其中，……」仅为兜底，不是默认句式。
- 说明书具体实施方式：在此基础上**更充分地展开解释**——给出计算方式、取值范围、物理含义、举例，让名词的内涵彻底清楚。
- 两者不重复也不矛盾：权利要求是精炼、可读的法律表述，说明书是详细的技术解释；本 skill 要求的就是把这段详细解释放在对应实施例**权利要求复述段之后、"具体而言"展开段之前**。

## 撰写结构示范

```
【复述权利要求】
（复述权利要求）……当所述调节比大于1.5时，锁定所述调节杆；

【再释义】
本实施例中，调节比是指调节杆伸出长度与壳体高度的比值。比值越大，伸出越多。比值达到 1.5 及以上时，调节杆进入需要锁定的行程。

【再展开】
调节杆……（此处可直接用「调节比」，不必再解释）
```

即：新名词的释义段落排在该条权利要求复述段之后、"具体而言"展开段之前，作为读懂后续展开段的前提。

## 检查清单

- [ ] 该条每个新定义名词是否都在复述之后、展开之前解释清楚了？
- [ ] 释义是否用「某某是指」起句，而不是「具体而言／进一步地／所述某某」？
- [ ] 展开段里是否还在解释名词，或释义被放到展开之后？
- [ ] 释义是否比权项「其中」句更充分，且没有用未定义词解释未定义词？

## 应用范围

适用于任意技术方案类型（结构类/方法类/算法类）说明书"具体实施方式"部分的撰写与质检。撰写时按"复述权利要求 → 释义新名词 → 具体而言展开"的顺序逐条动笔；正式质检时由  挂接本 skill 核对释义顺序，清楚性专项仍按 `说明书具体实施方式清楚性与逻辑一致性规范` 核对。与 `embodiment-drafting`（复述+展开的两段结构）配合使用：本 skill 负责"释义排在复述段之后、展开段之前"这一顺序，后者负责实施例本身"怎么复述、怎么展开"。
