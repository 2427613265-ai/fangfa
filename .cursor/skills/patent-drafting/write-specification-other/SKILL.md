# 说明书其他部分（架构）

**说明书中除具体实施方式以外的章节。** 本阶段只定职责与契约，各章写法待补。

## 架构角色

覆盖说明书里「非实施例」部分，并保证发明内容与独权一致。具体怎么实施留给 `write-embodiments`。

## 何时启用

- 已有理解稿与独权，需要说明书的框架章节
- 用户只要背景 / 发明内容 / 技术领域 / 附图说明等
- 全流程中可与实施例并行

## 门禁

- 必须已有理解稿、命名表；写「发明内容」时必须已有独权。
- 仅有交底、用户只要背景草稿时：可先写背景，但须标明发明内容待独权后再补。
- **不写**具体实施方式正文（交给 `write-embodiments`）。

## 输入 / 输出契约

**输入**

- 理解稿（问题、现有技术、效果）
- 命名表（`03-naming.md`）
- 独权（优先读 `04-claims.md` 正式用名独权；及从权，用于发明内容展开）
- 附图清单（有则用）

**输出**（`06-specification-other.md`）

章节范围（细目待补，默认包括）：

- 发明名称
- 技术领域
- 背景技术
- 发明内容（目的、技术方案、有益效果）
- 附图说明（无图可空）

不含：具体实施方式。

## 上下游

- 上游：理解稿、命名表、独权、从权
- 并列：`write-embodiments`
- 总控与实施例合并为完整说明书

## 方法 / 结构

架构预留分支（规则待补）：两章发明内容的表述方式不同，但都须回指对应独权。

## 内容待补

- 各章节篇幅与写法
- 发明内容与独权/从权的同步规则
- 背景技术与理解稿「问题」的对应，禁止编造对比文件
