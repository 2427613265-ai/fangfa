# 说明书其他部分

覆盖说明书里「非具体实施方式」的章节。发明内容须与独权对齐；用词以 `03-naming.md` 为准。具体怎么实施交给 `write-embodiments`。

本 skill **只编排顺序并落盘**。各章是同级独立 skill（侧边栏与本入口并列），也可单独 `/` 调用。改某一章就打开对应 `SKILL.md`。全流程时按下面顺序 **读取并遵循**。

## 何时启用

- 已有理解稿、命名表，且权利要求书已基本定稿（`04-claims.md`）
- 用户只要技术领域 / 背景 / 技术问题 / 有益效果 / 摘要
- 全流程中与实施例可交错：领域～有益效果可先写；**摘要放最后**（技术领域已定，建议实施例也完成后再写）

无权利要求书时：可先写背景草稿，须标明发明内容与摘要待权项后再补。不写具体实施方式正文。

## 顺序（分步）

默认一轮一章。用户说一次写完除外。每章先启用对应子 skill 再动笔。

| 步 | 章节 | 改这里 / 启用这个 |
| --- | --- | --- |
| 1 | 技术领域 | [`spec-technical-field`](../spec-technical-field/SKILL.md) |
| 2 | 背景技术 | [`spec-background`](../spec-background/SKILL.md) |
| 3 | 技术问题陈述 | [`spec-technical-problem`](../spec-technical-problem/SKILL.md) |
| 4 | 技术方案 | 用说明书口吻复述独权（及需要时关键从权），术语用命名表；不在此写实施例细节 |
| 5 | 有益效果 | [`spec-beneficial-effects`](../spec-beneficial-effects/SKILL.md) |
| 6 | 附图说明 | 本仓库该章细则未拉取；有图则按命名表列图序与标记，不得编造新图 |
| 7 | 说明书摘要 | [`spec-abstract`](../spec-abstract/SKILL.md)（≤300字；技术领域用词与第1步一致） |

禁止：先写摘要再写技术领域；把实施例写进本 skill。

专利名称三处逐字一致：权利要求书标题、技术领域「具体涉及」、背景收尾句、技术问题陈述、摘要。

## 输入 / 输出

**输入**

- `01-understanding.md`（场景、现有技术、效果；背景不得编造对比文件文号）
- `03-naming.md`
- `04-claims.md`（正式用名独权及从权；无则读构思稿并标明未优化）
- 附图清单（有则用）

**输出**（`cases/<案号>/06-specification-other.md`）

发明名称；技术领域；背景技术；发明内容（技术问题、技术方案、有益效果）；附图说明（可空）；摘要。

## 上下游

- 上游：理解稿、命名表、权利要求书
- 并列：`write-embodiments`（摘要建议在实施例之后）
- 总控汇编进 `specification.md`

## 边界

- 不写具体实施方式
- 背景第二段只写行业常见做法，不要贴着本申请创新骨架写近似方案
- 技术问题陈述与有益效果只对应独权核心特征，不堆从权问题/效果
