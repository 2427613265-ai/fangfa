# 说明书撰写

撰写与权利要求书相支撑的方法类专利说明书。若用户只要内部工法体例，可改用「工法章节」输出，但仍保持步骤可实施、参数可核对。

## 何时使用

- 用户要求写/改说明书全文或某一章（背景、发明内容、实施例等）
- 已有权利要求，需要说明书支撑
- 已有交底理解稿，需要形成完整说明书

## 开始前对齐

优先读取上下文中的交底理解稿与权利要求书。若缺失，确认：

1. 发明名称（方法类）
2. 独立权利要求及主要从权（或核心步骤）
3. 至少一个可实施的完整实施例素材
4. 现有技术与缺陷（来自交底）
5. 附图需求（流程图等）

无权利要求时，可先按交底写说明书草稿，并在文末提示应用 `write-claims` 对齐。

## 默认章节

1. **发明名称**
2. **技术领域**
3. **背景技术**
4. **发明内容**（目的、技术方案、有益效果）
5. **附图说明**（无图可省略）
6. **具体实施方式**

按用户要求可只输出部分章节。

## 各节要点

### 技术领域

简要说明所属领域与主要用途，1–3 段即可。

### 背景技术

客观写现有做法及问题；每个问题应能被本发明内容/实施例回应。不贬低具体厂商；不编造对比文件细节。

### 发明内容

- **目的**：对应背景问题。
- **技术方案**：与独立权利要求核心步骤一致，可补充优选手段。
- **有益效果**：与特征对应；能量化仅使用用户提供数据，否则写清机制、标待补。

### 具体实施方式

- 至少一个完整实施例，覆盖独权全部必要步骤。
- 写清材料、设备、参数（范围+优选值若有）、操作顺序、控制与完成标准。
- 可写替代手段、不同工况变例；变例不得与权项矛盾。
- 参数缺失处用 `【待补充】`，禁止虚构试验数据。

## 与权利要求的一致性

- 权项中的步骤名称、顺序、关键限定，说明书中须有对应支撑。
- 独权特征不得仅出现在权项而实施例从未实现。
- 若发现权项过宽/过窄或用语不一致，先指出并给出说明书侧改法；需要改权项时建议转 `write-claims`。

## 输出约定

- 中文 Markdown，章节标题清晰。
- 默认输出完整说明书；用户指定章节则只写该部分。
- 文末附：**待补充清单**、**与权利要求对齐说明**（若已有权项）。

## 衔接

- 上游：`understand-disclosure`、`write-claims`
- 质检：`quality-check`
